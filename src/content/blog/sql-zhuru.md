## SQL注入
### SQL注入原理
产生的原因：程序把用户输入的数据当成了SQL代码去执行。也就是变量没有做处理，直接拼接进了SQL语句。

注入的本质：数据与代码边界模糊。你输入的东西，打破了原本SQL语句的闭合结构（比如加了一个单引号 '），从而改变了SQL的逻辑。

### SQL注入的方法
元数据（Data about data）：

解释：黑客注入了之后，第一步往往是“脱库”（看有哪些库、表、字段）。元数据就是描述数据库结构的数据。

实战：MySQL里有个自带的库叫 information_schema，里面的 TABLES 和 COLUMNS 表记录了所有库名、表名、列名。黑客用注入点查这里，就能知道你的密码存在哪张表的哪个字段。

判断注入点闭合类型：

攻击者不知道你代码里怎么写的，所以得试探。是数字型（id=1）、字符型（id='1'）、还是带括号的（id=('1')）？闭合符号是单引号还是双引号？

你刚才的实操：admin' OR 1=1 -- 就是在测试，发现前面是单引号闭合的。

联合查询注入 (UNION)：

场景：页面有回显（你能看到查询结果）。

手法：用 ORDER BY 猜出前面查了几列，然后用 UNION SELECT 1,2,3 把数字替换成数据库名、表名。例题 moectf2025 考的就是这个。

报错注入：

场景：页面不回显数据，但会把数据库的报错信息打印在网页上。

手法：利用特殊函数（如 extractvalue() 或 updatexml()），故意制造语法错误，把你要查的数据（比如库名）拼在错误提示里弹出来。例题 [SWPUCTF 2021]error 就是典型。

布尔盲注：

场景：页面既不回显数据，也不报错。但查询有结果时页面显示“登录成功”，没结果显示“登录失败”。

手法：构造 AND 1=1（页面正常）和 AND 1=2（页面异常），然后逐个字母去猜，比如 AND substr(database(),1,1)='t'。

时间盲注：

场景：页面无回显、不报错、连真假状态都一样（完全像死水）。

手法：利用 SLEEP() 函数。如果猜对了，页面卡顿3秒；猜错了，瞬间加载。例题 [BaseCTF2024] only on... 就是这个路子。

堆叠注入：

场景：支持一次执行多条语句（用分号 ; 隔开）。

手法：1'; DROP TABLE users; --。危害极大，能直接删表。但不是所有环境都能用（比如PHP的PDO默认不支持）。

二次注入：

场景：你刚才刚刚实操过的。输入时存进数据库（安全），程序在另一处从数据库取出来拼接执行（危险）。因为绕过了入口的防御（WAF），非常隐蔽。

宽字节注入：

场景：数据库编码是 GBK 时。

手法：代码用 addslashes 把单引号 ' 转义成了 \'，但黑客输入 %df%27，在GBK编码下，%df 会和反斜杠 \ 结合成一个汉字，导致后面的单引号逃逸出来。

### SQL注入一些绕过
现在的网站大多有 WAF（防火墙），会拦截 SELECT、UNION、空格等关键字。

绕过手法：大小写混写（SeLeCt）、双写（UNioN）、用注释代替空格（/**/）、编码绕过等。
