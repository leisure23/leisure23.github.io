大一那年我学完数据结构，期末考了 91 分。半年后有人问我「红黑树和 AVL 树的区别」，我张了张嘴，只记得两个名字都带颜色。

这件事让我有点慌。**分数能证明我背过，不能证明我会。** 于是我开始写这个博客。

## 写下来，是最便宜的自我检测

学习的错觉有很多种：

- 看视频时觉得「懂了」，其实是跟着讲解的节奏走，大脑在摸鱼；
- 抄笔记时觉得「记住了」，其实只是把 PPT 搬到了本子上；
- 考前刷题觉得「会了」，其实是记住了这几道题的形状。

真正的检验只有一个：**你能不能用自己的话，把它讲给一个不懂的人听。**

写博客就是强制自己完成这件事。因为一旦开始写，你就会发现：

1. 你以为懂的地方，其实是「我记得这里有个公式」；
2. 你写不出来的句子，就是你理解断掉的地方；
3. 你解释不清的概念，说明你还没真的想明白。

费曼学习法说的就是这个：**讲不清，就是没学会。**

> 不要等到「学明白再写」。写作本身就是学明白的过程。

## 为什么不发在别人的平台上

我也试过在论坛发帖，但很快就不想写了：

- 排版难受，代码块一贴就乱；
- 广告和推荐流会把人从文章里拽走；
- 平台会不会倒、笔记能不能导出，都不由我决定。

自己的站就不一样了：**文章是我硬盘里的 `.md` 文件**，一篇文章就是一段纯文本。哪天这个框架不流行了，我把文件拷走就是，谁也拿不走。

## 这个博客是怎么搭起来的

技术上很简单，一共三个东西：

| 东西 | 干什么 | 学习成本 |
| --- | --- | --- |
| Astro | 把 Markdown 变成网页 | 会用 Markdown 就行 |
| GitHub | 存代码，同时当服务器 | 会 `git push` 就行 |
| GitHub Actions | 每次推送后自动重新构建并发布 | 一次配置，之后不用管 |

写作的流程是这样的：

```bash
# 1. 新建一篇文章（会自动生成带元信息的模板）
npm run post "红黑树到底红在哪"

# 2. 本地预览，边写边看
npm run dev

# 3. 提交，剩下的交给 GitHub
git add . && git commit -m "新文章" && git push
```

推送之后大约一分钟，网站就更新了。整个过程没有数据库、没有服务器、没有月费。

## 这个博客里会有什么

- **课程笔记**：数据结构、算法、计网、操作系统。不是抄 PPT，是抄「我当时卡在哪」。
- **踩坑记录**：配环境配了三小时的那种，写下来，下次省两小时。
- **原理追问**：从「知道」往「为什么」再挖一层。

写得慢一点没关系。宁可一个月一篇，也不要一个月十篇水文。
